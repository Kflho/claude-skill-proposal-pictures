# 三类图的版式规范

> 画布统一 `viewBox="0 0 1600 900"`（矩阵图可用 `0 0 1200 1000`）；白底；坐标取整。
> 三张图配套使用：**框架图**说"我在哪、我支撑谁"，**路线图**说"我怎么走"，**矩阵图**说"我为什么这么走"。

---

## 1. 总体框架图（回答：本部分如何支撑上级？与兄弟部分什么关系？）

```
┌ 标题：<本部分名>总体框架 ───────────────────────────────────────────┐
│ ┌────────────── 上级课题/项目 全称（通栏，语号最大） ──────────────┐ │
│ └─────────────────────────────────────────────────────────────┘ │
│        ▲（向上支撑：一句话，4~6 字）                              │
│ ┌────────────┐  ┌──────────────┐  ┌──────────────────────────┐  │
│ │ 兄弟一      │─▶│              │─▶│ 子内容 1（~10 字）        │  │
│ │ （弱化色）  │  │  本部分       │  │ 子内容 2                 │  │
│ ├────────────┤  │  核心名       │  │ 子内容 3                 │  │
│ │ 兄弟二      │─▶│ （本子课题）  │  │ 子内容 4（可带协同注）    │  │
│ ├────────────┤  └──────────────┘  └──────────────────────────┘  │
│ │ 兄弟三      │───────┘            ┌──────────────────────────┐  │
│ └────────────┘                     │ 支撑产出（强调色）         │  │
│                                    │ · 成果物                  │  │
│                                    │ · 曲线/清单               │  │
│                                    │ · 相对指标（带基线）       │  │
│                                    └──────────────────────────┘  │
│ 底部通栏：支撑的系统级指标（由 XX 环节考核）：…（与正文逐字一致）  │
│ 图注（小字，可选）：计时口径 / 基线 / 术语说明                     │
└─────────────────────────────────────────────────────────────────┘
```

**要点**

- 兄弟部分用**弱化色**，本部分与子内容用**主色**，产出用**强调色**：一眼看出主角。
- 兄弟 → 本部分的连线**必须配 4~10 字标签**，写明"给了什么"（如"干扰残余水平→约束项"）。
- 子内容 3~4 条，每条 **10 字左右**；上级给的示例条目**原样照抄**，不缩写不改词。
- **产出框**是很多人漏掉的一格：交付物（软件/报告/样件）＋相对指标（带基线）＋时间类指标（带口径），
  以及"这条指标由谁考核"。没有产出框，图就撑不起考核指标。
- 底部通栏写**承接的系统级指标**，与正文该行**逐字一致**（含限定条件与去向）。

## 2. 技术路线图（回答：技术路线怎么走？）

```
┌ 标题条：<本部分名>　技术路线 ──────────────────────────────────────┐
│ 层次一　<阶段名>                                                   │
│ ┌ 模块 1 ┐ → ┌ 模块 2 ┐ → ┌ 模块 3 ┐                              │
│ │ 小示意  │   │ 小示意  │   │ 小示意  │                              │
│ │ 标题    │   │ 标题    │   │ 标题    │                              │
│ │ 说明行  │   │ 说明行  │   │ 说明行  │                              │
│ └────────┘   └────────┘   └────────┘                              │
│                    ▼ 动作词（2~4 字，如"建模基准"）                  │
│ 层次二　<阶段名>                                                   │
│ ┌ 模块 ┐ → ┌ 模块 ┐ → ┌ 模块 ┐                                    │
│                    ▼ 动作词                                        │
│ 层次三　<阶段名>                                                   │
│ ┌ 模块 ┐ → ┌ 模块 ┐ → ┌ 模块 ┐                                    │
│                    ▼ 动作词                                        │
│ 验证带（强调色）：统一仿真平台对比试验（基线 A／基线 B）→ 三阶段验证 │
└─────────────────────────────────────────────────────────────────┘
```

**要点**

- **2~3 条层次带**为宜；每条带一个带标题（`#4A7EBB` 底 + 白字），带内固定 3 个模块，横向箭头串联。
- 带间**居中向下箭头 + 2~4 字动作词**，动作词要说明"上一层给下一层什么"（建模基准 / 分配策略 / 求解实现）。
- 层次是**递进**关系，不是并列清单：若两层可以互换，说明层次划分错了。
- 模块内的"小示意"用简单几何（方框、圆、虚线）表达，不要塞照片或复杂插图。
- 验证带写**对比基线全名**与验证阶段；基线名与正文一致。

## 3. 研究计划矩阵（回答：目标→问题→内容→方法→验证如何对齐？）

```
        ┌ 目标需求（通栏，3~5 行，说明需求与约束）──────────────────┐
  竖    └──────────────────────────────────────────────────────────┘
  排    ┌ 关键问题 ────────────────────────────────────────────────┐
  标    │ 问题一 │ 问题二 │ 问题三 │ 问题四（各 1 行 + 1 行说明）    │
  题    └──────────────────────────────────────────────────────────┘
  条    ┌ 研究内容 ────────────────────────────────────────────────┐
  （    │ 4-1 │ 4-2 │ 4-3 │ 4-4（编号 + 标题，可折 2 行）           │
  旋    └──────────────────────────────────────────────────────────┘
  转    ┌ 子内容与关键方法 ────────────────────────────────────────┐
  90°） │ 4-1 │ 4-2 │ 4-3 │ 4-4（每条 2~3 个 bullet）               │
        └──────────────────────────────────────────────────────────┘
        ┌ 实验验证（强调色，3 格：仿真 / 曲线 / 三阶段）─────────────┐
        └──────────────────────────────────────────────────────────┘
```

**要点**

- **列数 = 研究内容条数**，且"问题 N ↔ 内容 N ↔ 方法 N"**竖向严格对齐**：这是这类图的灵魂。
- 4 列时单格约 230px：格内正文 14px、编号/header 15px；标题用"编号一行 + 标题一行（必要时折两行）"。
- 某条内容放不下时**按词间折行**（如"时频、频段、功率 / 随任务自适应分配"），不要拆成两个 bullet。
- 「目标需求」行是通栏（讲需求与硬约束），「实验验证」行是跨条目的（讲验证手段），都不要按列拆。
- 若上级示例只给 3 条、而你的内容有 4 条：**先对齐上级的条数与名字**，再谈排版。

## 4. 三图之间的分工（避免重复）

| 信息 | 应该在哪张图 | 不该在哪张图 |
| --- | --- | --- |
| 与上级/兄弟的关系、支撑产出 | 框架图 | 路线图 |
| 技术层次与递进关系 | 路线图 | 框架图 |
| 目标—问题—内容—方法—验证的对应 | 矩阵图 | 框架图 |
| 指标值 | 框架图（产出框、承接通栏）＋正文 | 路线图（只写方法，不写指标值） |

三张图都**不写**：未定的数值、做不到的承诺、与正文不一致的术语。

## 5. 连线规范（视觉语言必须统一）

> 一次真实返工换来的规则：同一张图里**混用斜线与直角折线**，会被一眼看成"不专业"；
> **并列项之间画箭头**，会被读成"有先后顺序"，把方案逻辑讲错。

### 5.1 只用正交折线

| 做法 | 判定 |
| --- | --- |
| 水平/垂直线段 + 直角折点（`<polyline>` 或 `<line>` 拼） | ✅ 唯一允许的连线形态 |
| 斜线、扇形发散线、曲线连接 | ❌ 禁止（除"小示意"内部图形） |
| 两点同高/同列时退化为一条直线 | ✅ 允许（同一语言的特例） |

### 5.2 一对多 / 多对一：用母线，不用扇线

```
一对多（一路出、N 路分）              多对一（N 路进、一路入）
核心框 ──┬──▶ A                         A ──┐
         ├──▶ B                         B ──┼──▶ 目标框
         ├──▶ C                         C ──┘
         └──▶ D
```

- 出线：核心框右边缘 → 水平短线 → **竖母线** → N 条水平支线（每条一个箭头）。
- 支线的 `y` 一律对准目标框的中心线；箭头一律射入目标框边缘（留 4~6px）。
- 母线两端不要超出最上/最下支线；母线本身不带箭头。

### 5.3 箭头只表达三种关系

| 可以画箭头 | 不要画箭头 |
| --- | --- |
| 因果/流转（需求→问题→内容→方法→验证） | **并列项之间**（问题一↔问题二、4-1↔4-2 是并列，不是流程） |
| 对应关系（同列的上下级，1:1） | 单纯为了"连起来好看" |
| 支撑/交付（谁给谁什么，带标签） | 没有标签的模糊连线 |

### 5.4 数量不匹配时：用通栏表达"跨条目"，不要强行对齐

矩阵图里若上行 4 列、下行只能给 3 格（因为下行是跨条目的，如"实验验证"）：
**把下行做成通栏（1 个宽框）＋分隔线＋N 个居中标签**，上行的箭头照列心均匀射入通栏。
反过来硬把 3 格对上 4 列（箭头落在 x=322/668/1014 这种"看起来随便"的位置）＝ 读者一眼看出错位。

### 5.5 标签写法

- **同一张图里标签的锚点与 x 坐标统一**（推荐：`text-anchor="start"` + 同一 `x`，形成一条标签列）。
- 标签放在**线的外侧**：线在标签下方 → 标签在上；折线向上拐 → 标签在线的下方。
- 标签与线的净距 ≥8px，与相邻方框的净距 ≥8px（`check_overlap.py` 会查）。
- 一条连线一个标签，4~10 字，写"给了什么"而不是"相关/有关"。

## 6. 设计系统（开工前先定这张表，画完用 `check_consistency.py` 验）

同一类元素在同一张图里**只能有一种处理**。"有的居中、有的左对齐"＝读者一眼看出乱，
而几何自检查不出这类问题（真实事故：一张矩阵图 28 处居中、17 处左对齐）。

| 角色 | 锚点 | 字号 | 颜色 | 说明 |
| --- | --- | --- | --- | --- |
| 图主标题 | middle | 30 | `#FFFFFF`（深色条上） | — |
| 通栏标题（上级/课题名） | middle | 24 | `#1F2937` | — |
| 行/列标签块（竖排或色块） | middle | 17 | `#FFFFFF`（色块上） | 各标签块内缩一致（如统一 20px） |
| 单元格表头 | **middle** | 15 | `#2F6FB0` bold | 问题一 / 4-1 |
| 表头分隔线 | 居中，长 = 格宽 30%~80% | 2（opacity .45） | `#2F6FB0` | 有无必须全组一致 |
| 单元格正文 | **middle** | 14 | `#1F2937` | 与表头同列心 |
| 单元格注释小字 | middle | 12 | `#4B5563` | 如"（与子课题二协同）" |
| **通栏段落** | **start**（左对齐，缩进 24） | 17 | `#1F2937` | 如"目标需求"四行 |
| **通栏并列项** | **middle**（等分居中） | 17 | `#1F2937` | 如"实验验证"三格 |
| 连线 | 正交折线，线宽统一 | 2（细分 1.5） | `#2F6FB0` | 箭头语义见 §5.3 |
| 连线标签 | start，同一 x | 14 | `#4B5563` | 线上外侧 |

**三条对齐规则**（记住这三条，就不会"有的居中有的不居中"）：

1. **单元格里的东西一律居中**（表头、正文、注释都居中于列心）；
2. **通栏里的段落左对齐**（长句段落居中会显得散）；
3. **通栏里的并列项居中**（等分居中）。
